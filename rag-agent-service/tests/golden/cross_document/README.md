# 跨文档审查 · 评估基线（golden set）

这是跨文档矛盾/职责冲突检测的**尺子**。没有它，后面调 prompt 全是盲调。

## 这把尺子解决的问题（对应此前 14 问的 Q1–Q4）

- **Q1 分布一致**：样例应尽量用**真实 SOP 片段**改写，别用纯手编玩具。当前初始样例
  是手编的最小可用集，**待正大天晴真实文件 OCR 后必须替换/补充**（见下方"局限"）。
- **Q2 类不平衡**：真实世界是"上千句里两三处矛盾"。所以 golden set 里**多数组应是
  无矛盾（clean）**，少数有矛盾。指标**分开报**：有矛盾组看召回率，无矛盾组看误报率。
- **Q3 命中定义写死**：预测矛盾与标注矛盾，只要 **topic 相同 + 涉及同一对文件** 即算
  召回命中（不要求数值/原话也对）。数值/原话对不对，另算 `precision_detail` 子指标。
  这条规则固定，不许中途改，否则指标不可比。
- **Q4 随机性**：判定一律 temperature=0；评估对每组**跑 3 次取众数**，报均值与方差。
  方差过大（如召回率波动 >±10%）说明 prompt 不稳，先改 prompt 再看数字。

## 标注文件结构（每个 case 一个 `*.json`）

```json
{
  "set_name": "洁净度矛盾-case1",
  "files": [
    {"filename": "A_洁净区管理规程.txt", "version": "v1"},
    {"filename": "B_环境监测SOP.txt", "version": "v1"}
  ],
  "expected_conflicts": [
    {
      "topic": "洁净度等级",
      "files": ["A_洁净区管理规程.txt", "B_环境监测SOP.txt"],
      "detail": "A说灌装间D级，B说灌装间C级"
    }
  ],
  "expected_responsibility_issues": [
    {"type": "职责分离冲突", "role": "张三", "detail": "既是操作人又是复核人"}
  ],
  "clean_topics": ["温湿度"]
}
```

- `files`：本组参与的文件（放同目录的 `.txt`）。`version` 用于验证"同文件不同版本
  不误报为矛盾"（Q14）。
- `expected_conflicts`：**该被抓到**的矛盾。空数组 = 这是一个 clean 组（测误报）。
- `expected_responsibility_issues`：该被抓到的职责问题。
- `clean_topics`：这些主题**故意放了看似不同、实则合理**的差异（如不同洁净区等级不同），
  预测里若对这些 topic 报矛盾 → 计为**误报**（Q6/Q2 假阳性防护）。

## 指标定义（评估器输出）

- `recall`：有矛盾组里，`expected_conflicts` 被命中的比例。
- `false_positive_rate`：无矛盾组 + clean_topics 上，被错报的矛盾数 / 组数。
- `precision_detail`：命中的矛盾里，detail/数值也基本对的比例（子指标，供参考）。

## 局限（必须诚实告知使用者）

1. 初始样例是**手编最小集**，分布**不代表**真实 468 页 SOP。真实文件到手前，
   这里的高分**不能**外推到生产。
2. 本尺子只覆盖**已列入的 topic**；topic 之外的矛盾查不到，也测不到——这是系统性盲区，
   报告里不得暗示"已全面覆盖"。
