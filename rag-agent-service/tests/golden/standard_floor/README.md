# 3.2a 标准底线核查 · golden 评估集

验证"企业量化标准是否低于法规底线"的判定准确性。**判定是纯规则（方向性比较），
不调模型**——所以这个 golden 主要量"规则比对 + 抽取喂进来后"的判定对不对。

## 判定的三种结果（对应 verdict）

| verdict | 含义 | 例 |
|---|---|---|
| `PASS` | 企业标准 ≥ 法规底线（达标） | 法规底线微生物≤100，企业≤50，更严 → 达标 |
| `BELOW` | 企业标准 < 法规底线（不达标，飞检高危） | 法规底线≤100，企业≤200，更松 → 不达标 |
| `UNKNOWN` | 无法自动判定，交人工 | 属性不在方向序表里 / 法规无明确底线 / 值解析不出 |

## 为什么必须有 UNKNOWN 这一类

这是本项目铁律"系统只堆疑点、不裁决"的落地：判不了的**明确交人工**，
绝不瞎判成 PASS（漏掉真问题）或 BELOW（误报）。golden 必须包含 UNKNOWN 样例，
证明系统在没把握时会诚实退让，而不是硬猜。

## 结构

每个 case 一个 `expected.json`：
- `assertions`: 直接给结构化企业断言 `{object, attribute, value}`（跳过 LLM 抽取，
  单测判定逻辑本身；抽取质量另由跨文档那套投票机制保证）
- `expected`: 每条断言的预期 verdict + 命中的法规底线 id

## 诚实边界

- golden 是手编的，覆盖常见属性（洁净度/微生物/温度/频次）。真实文件的表述更杂，
  Q1（真实分布）同样未闭合，等 OCR 后用真实片段补充。
- 方向序表（regulation-floor.json）覆盖不到的属性一律走 UNKNOWN，这是设计而非缺陷。
