# LLM Gateway 成本预测与结算

## 1. 设计目标

调用前无法知道生成式模型的最终输出长度，因此系统不再把 tokenizer 估算包装成真实账单，而是明确区分三种口径：

- `ESTIMATED`：调用前使用输入 token + 条件分位数输出预测进行额度预留。
- `REPORTED`：调用完成后使用厂商响应或流式 usage 结算。
- `RECONCILED`：未来接入厂商 Costs/账单 API 后形成的财务最终值。

当前工程已经实现前两层；第三层需要不同厂商的 Billing Adapter 和定时对账任务。

## 2. 调用链

```text
最终 Prompt
  -> 按候选 Endpoint 计算输入 token
  -> 在线条件分位数回归预测 P50/P90/P95/P99
  -> 使用 P95 + Conformal correction 预留 token/预计费用
  -> 调用 primary/retry/fallback
  -> 优先读取 provider usage
  -> 按缓存读写、价格阶梯和汇率计算实际费用
  -> Redis/Memory 原子冲正预留与实际值差额
  -> 记录预测误差，在线更新下一次分位数模型
```

客户端显式提供 `max_tokens/max_completion_tokens` 时，预测预留不会超过该值；未提供时，网关不会为了成本预测擅自注入较小上限，因此不会截断正常回答。

## 3. 分位数回归

`QuantileRegressionOutputTokenPredictor` 为每个 `provider:model` 分别维护 P50、P90、P95、P99 四个在线线性分位数模型。训练目标采用 pinball loss，调用成功后的实际 `completion_tokens` 是监督标签。

当前特征包括：

- 输入 token 的对数；
- messages 数量；
- tools 数量；
- `rag_context_tokens`；
- 是否要求 JSON/结构化输出；
- temperature；
- provider/model 独立状态。

样本不足时使用配置的冷启动值；达到 `min-samples` 后，使用最近误差窗口计算 P95 conformal correction。最终预测会强制满足 `P50 <= P90 <= P95 <= P99`。

当前实现适合冷启动和在线演示，模型状态保存在单 JVM。生产多实例下一步应把使用报表作为训练集，定时训练 LightGBM Quantile 模型并导出 ONNX；`OutputTokenPredictor` 接口保持不变，只替换实现。

## 4. 预留和结算

`QuotaService` 已从旧的 `reserve(prompt) + record(completion)` 改为幂等状态机：

```java
UsageReservation reserve(userId, requestId, estimatedPrompt, estimatedCompletion, estimatedCost);
void settle(userId, reservation, actualUsage);
void release(userId, reservation);
```

调用前同时预留预计 Prompt、Completion 和成本；调用成功后用实际 `GatewayUsage` 计算 delta，Redis Lua 或内存实现会把差额增加或释放。全部路由失败时释放预留，无法确认的厂商失败费用仍需未来账单对账。

同一个 reservation 只有 `RESERVED -> SETTLED` 或 `RESERVED -> RELEASED` 一次有效转换；重复结算/释放为 no-op，避免 Reactor 重放或网络重试造成二次冲正。

## 6. 响应和报表

非流式响应的 `gateway` 元数据新增：

```json
{
  "costCurrency": "CNY",
  "priceVersion": "2026-07-14",
  "usageSource": "PROVIDER_RESPONSE",
  "costStatus": "REPORTED",
  "outputTokenPrediction": {
    "p50": 900,
    "p90": 1800,
    "p95": 2400,
    "p99": 4200,
    "reserved": 2400,
    "conformalCorrection": 120,
    "sampleCount": 860,
    "modelVersion": "online-linear-quantile-v1"
  }
}
```

Usage 报表保存预测值、P95、模型版本、样本量和实际 completion token，并汇总平均绝对预测误差。流式 OpenAI-compatible 请求自动发送 `stream_options.include_usage=true`，优先使用最终 usage chunk；不支持 usage 的服务才回退到累计内容 tokenizer。

## 7. 仍需继续完成的财务级能力

- Provider Attempt 级不可变账本，分别记录 primary/retry/fallback 的潜在费用；
- 各厂商 Usage/Costs API 定时同步和账单冲正；
- 汇率服务及生效时间版本，而不是人工环境变量；
- 本地 vLLM/Ollama 按 GPU-second、CPU、内存、电力和折旧核算；
- LightGBM Quantile 离线训练、模型注册、灰度和漂移告警。
